Credential Phishing: Attack & Defense

This lab demonstrates why traditional passwords are vulnerable to phishing, and how FIDO2 passkeys are immune by design. No real attacks are performed.

Educational Simulation
Scenario A
Legacy Password System
Vulnerable

An attacker clones the college login portal on http://fake-college-portal.xyz and sends phishing emails. When the victim enters their password, it is intercepted in transit.

1
Attacker clones login page at a lookalike domain
2
Victim receives phishing email, clicks the link
3
Victim types password → attacker intercepts it
[BREACH SIMULATED] Attacker's proxy intercepted the form data:
Captured:
Attack result: Account compromised. MFA can be bypassed via session hijack.
Why this works

Passwords are reusable secrets. A copied login page is indistinguishable from the real one. The victim's credential works on any server that receives it.

Scenario B
CyberNova Passkey System
Phishing-Resistant

The same phishing site targets a CyberNova user. The victim attempts to authenticate, but the FIDO2 authenticator refuses to sign the challenge because the domain does not match.

1
Victim visits fake-college-portal.xyz via phishing link
2
Authenticator hashes the real origin (RP ID) — it does not match the registered domain
3
Private key refuses to sign → server logs attack → no credential leaked
[CRYPTOGRAPHIC DEFENSE ENGAGED]
Browser origin check: http://fake-college-portal.xyz ≠ localhost (RP_ID)
FIDO2 mechanism: The authenticator signs with SHA-256(RP_ID). The rogue domain produces a different hash — the private key refuses to generate a valid assertion.
Server defense: Origin mismatch detected. Phishing block logged to SOC.
Why this fails for the attacker

Passkeys are domain-bound. The private key never leaves the device and only produces a valid signature for the exact registered origin. A copied login page on a different domain receives nothing usable.

Honey-Token Active Defense Demonstration

CyberNova embeds a decoy endpoint /api/admin/export-system-keys — a honeypot that looks like a leaked admin key export. Automated scanners, curious attackers, and crawlers who probe this URL are silently fingerprinted and logged to the SOC audit stream. No real keys exist at this endpoint.

What happens

The request is intercepted, the attacker's IP and headers are recorded, the event is logged as CRITICAL in the SOC stream, and a 403 is returned. No real credentials are exposed. Visit the Staff SOC Dashboard to see the event appear in real time.
